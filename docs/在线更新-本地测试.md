# 在线更新 —— 本地测试

**不用部署任何服务器**，在本地就能亲眼看到应用把自己更新掉。

## 原理

```
    ┌──────────────┐   ① 问一句"有新版吗"    ┌────────────────┐
    │  已装的旧版   │ ──────────────────────▶ │  本地更新服务器 │
    │  （0.1.0）   │ ◀────────────────────── │   latest.json  │
    └──────┬───────┘   ② 清单：0.1.1 + 签名   └────────────────┘
           │
           │ ③ 后台下载新包 → ④ 验签（公钥烧在客户端里）→ ⑤ 用户点重启
           ▼
    ┌──────────────┐
    │  新版 0.1.1   │
    └──────────────┘
```

要点：

- **签名**：更新包用 minisign 私钥签名，公钥烧在客户端里。验签不过一律不装 ——
  否则"能往这个更新地址放文件的人"就能给全公司推任意程序。
  **Tauri 强制要求签名**（试过删掉，它直接报 `missing field pubkey` 拒绝打包）。

### 签名私钥放哪儿（重要）

**跟服务器数据放在一起，不需要你额外记着保存任何东西：**

```
服务器数据目录/
  ├── kuaiban.db                ← 所有人的待办
  └── kuaiban-updater.key       ← 更新签名私钥
```

这样安排只有一个理由：**你本来就必须备份服务器数据**（丢了所有人的待办）。
让私钥搭上这趟车，就**不存在"要额外记住一个文件"这件事**——
而"要用户记着保存个东西"的设计，长期一定会丢。

查找顺序（第一个找到的就算）：环境变量 `KUAIBAN_UPDATER_KEY` →
服务器数据目录 → `./.keys/`（本地开发，已 gitignore）→ `~/.tauri/`。

### 万一真的丢了

不是灾难，是**一次性麻烦**：

```bash
node scripts/release.mjs --rotate-key
```

生成一把新钥匙，然后**手动给所有人装一次新版本**（发个下载链接就行），
之后自动更新照常。因为已装好的客户端里烧的是旧公钥，换钥匙它不认——仅此而已。

### 绝不要做的事

**不要把私钥提交进仓库。** 有了它就能签出装到全公司机器上的程序；
仓库一旦泄露（或有外部协作者），等于把所有人的电脑交出去。

### 发版：一条命令

```bash
node scripts/release.mjs 0.1.2
```

改版本号 → 打包 → 签名 → 生成更新清单，全自动。**你不需要碰私钥。**

## 步骤

### 1. 先打一个「旧版本」

```bash
export TAURI_SIGNING_PRIVATE_KEY="$HOME/Library/Application Support/com.kuaiban.server/kuaiban-updater.key"
pnpm --filter @kuaiban/desktop tauri build
```

> ⚠️ 是 `TAURI_SIGNING_PRIVATE_KEY`（直接给路径），**不是** `..._KEY_PATH`。
> 用错时打包照样出产物、只是**没有 .sig**，到签名那一步才报错 —— 打完 `ls *.sig` 确认一下。

产物在 `apps/desktop/src-tauri/target/release/bundle/macos/KuaiBan.app`。

**把它复制到别处留着**（下面要拿它当"已装的旧版"）：

```bash
cp -R apps/desktop/src-tauri/target/release/bundle/macos/KuaiBan.app /tmp/KuaiBan-0.1.0.app
```

### 2. 改版本号，再打一个「新版本」

版本号在 `apps/desktop/src-tauri/tauri.conf.json` 的 `version`（和 `Cargo.toml`）。
改成 `0.1.1` 之后重新打包：

```bash
pnpm --filter @kuaiban/desktop tauri build
```

### 3. 起本地更新服务器

```bash
node scripts/update-server.mjs --port 8899
```

它会自动扫描打好的更新包、生成 `latest.json`（含签名），并打印它发现了什么。
**如果提示"还没有更新包"**，说明打包时没设 `TAURI_SIGNING_PRIVATE_KEY_PATH`，
或者 `bundle.createUpdaterArtifacts` 没生效（应该在 `tauri.conf.json` 里是 `true`）。

### 4. 跑那个「旧版本」

```bash
open /tmp/KuaiBan-0.1.0.app
```

等 15 秒左右（启动后延迟检查，避免和读本地数据抢资源），然后打开设置面板的
**关于**一节，应该能看到：

```
快办 0.1.0                      [检查更新]
正在后台下载… 42%
▓▓▓▓▓▓▓▓░░░░░░░░░░░░
```

下载完成后变成：

```
新版本 0.1.1 已就绪，重启后生效
[ 立即重启并更新 ]
```

点它 → 应用重启 → 再看版本号已经是 `0.1.1`。**这就是完整的自更新流程。**

## 几个刻意的设计

**为什么不像普通软件那样弹对话框问"要不要更新"**

挂件是贴在屏幕边上的小东西，弹模态框会打断用户手头的事（而且用户可能在
全屏应用里）。所以：**后台悄悄查、悄悄下；装好了才在设置里显示一行**。
重启这个动作**必须用户点** —— 应用自己重启是有存在感的事，不能替他做。

**开发模式下为什么提示"不支持自动更新"**

`pnpm dev` 跑的是 `target/debug` 里的可执行文件，它没有被"装"过，
也就无所谓"更新"。只有打成正式安装包才有更新这回事。
所以开发模式下点「检查更新」会看到一句人话，而不是一串英文错误。

**为什么更新间隔是 6 小时**

内部工具一天发不了一次版；每次检查都是一次网络请求。启动后查一次，
之后每 6 小时一次就够。

## 正式发版时

1. 改版本号
2. `TAURI_SIGNING_PRIVATE_KEY_PATH=... tauri build` 打包
3. 把 `bundle/` 里的更新包和 `.sig` 传到服务器的更新目录
4. 按 `scripts/update-server.mjs` 里的格式生成 `latest.json`（正式环境用静态文件即可，
   不需要跑这个脚本 —— 它只是个本地测试用的替身）

> ⚠️ **Windows 与 macOS 要分别打包、分别上架各自的产物**，
> 清单里的 key 是 `darwin-aarch64` / `darwin-x86_64` / `windows-x86_64` 这种平台标识。
