## 四、⚠️ 一个已知隐患（知悉即可，不需要你们做什么）

`kuaiban.db` 是 SQLite **WAL 模式**（同目录有 `-wal` / `-shm`）。当前的备份方式是把整个数据目录打包；**如果打包的瞬间应用正在写库，可能拿到不一致的快照**，恢复时可能损坏或丢最近事务。

运维已提出修法（备份前先执行一次 `PRAGMA wal_checkpoint(TRUNCATE)`，无需安装任何软件），**待用户拍板后实施**。你们无需改动。

## 五、给项目 AI 的约定与提醒

1. **Stack 必须能从 Portainer 面板操作控制**（运维的硬性要求）—— **已满足**：
   `kuaiban-test`（`192.168.2.6:9000`）／ `kuaiban-production`（`192.168.2.10:9000`），**Endpoint ID 均为 `1`**，均为 **Compose 类型栈**，面板可见、可启停、可重建。

2. **部署后不要改容器名 / 项目名。** 本项目有应用因改名导致 Docker 卷重建、数据丢失的前例。

3. **测试机与生产机的端口完全相同，只能靠 IP 区分：**
   - 测试机 **`192.168.2.6:6522`**
   - 生产机 **`192.168.2.10:6522`**
   **改任何配置前务必先确认目标 IP**，别把生产当测试改。

4. **回源一律用 `ddns.bonnei.com`（动态域名），不要写死 IP。** 我们仓库的公网 IP 是动态的，会变。

5. **客户端安装包 / 自动更新**：服务端不配 `KUAIBAN_GITHUB_REPO` 时"读本地清单"。
   若要"跟随 GitHub Release"，**代码必须走 `api.github.com` 通道** —— 我们这里 **`github.com` 不可达**（超时），而 `api.github.com` 与 `objects.githubusercontent.com` 可达。
   如需服务端自己下载 Release 资源，必须用：
   ```
   GET https://api.github.com/repos/<owner>/<repo>/releases/assets/<asset_id>
       Header: Accept: application/octet-stream
   ```

6. **Portainer API Key**：描述名 `kuaiban-upgrade`，**两台各一把**，Endpoint ID = `1`。
   **CE 版不支持令牌有效期（永不过期）**，请纳入你们台账并约定定期复核（建议每年）。

7. **需要新增/变更运维动作**（开端口、改端口映射、改反向代理、改证书）**请提前告知，不要自行尝试** —— 路由器、防火墙、阿里云 NPM 由运维统一操作，误操作会影响其他在跑的业务。

## 六、关于证书续期（明确答复）

- **不需要任何人手动续期。**
- 阿里云 NPM 内置调度器**每小时**执行一次「Renewing SSL certs expiring within 30 days」，**到期前 30 天内自动续期**。
- **已有实证**：现有 12 张证书（其中最早的在 **2025-08-30** 创建）**全部有自动续期记录**（最近一次续期在 2026-08~09）。我们新加的 `kuaiban.bonnei.com` 会走同一机制，预计 **2026 年 12 月初**自动续期。
- **不需要 DNSPod Token**：自动续期依赖的是 **HTTP-01 验证**（域名解析到阿里云 NPM、80 端口从公网可达即可），与 DNSPod 无关。DNSPod 凭据只在改用 **DNS-01 验证**（例如要申请 `*.bonnei.com` 泛域名证书）时才需要。
