# 快办（KuaiBan）— 业务逻辑设计 v0.2

> 本文档只讨论**业务逻辑**（软件怎么运转），不涉及编程实现。
> 状态：**定稿候选**，待用户确认。
> 版本历史：v0.1 单机个人工具 → v0.2 公司内部多人网络版（重大变更）

---

## 0. 产品定位

**一个会自己记着事、到点会喊你、平时不烦你的桌面小挂件。**

面向人群：公司内部员工，共约 50 人以内，**每人数据独立、互不可见**。

三条设计铁律：
1. **极速捕获** —— 记录任何东西不超过 2 秒，不许选日期、选分类、选优先级。
2. **自动兜底** —— 没做完的事由软件主动搬到今天，不指望用户想起来。
3. **安静存在** —— 平时几乎看不见，只在"该提醒的时候"出现。

### 0.1 本次重大变更（v0.1 → v0.2）

| 项 | v0.1（原需求） | v0.2（确认后） |
|---|---|---|
| 部署形态 | 纯本地单机 | 客户端 + 公司服务器 |
| 用户 | 无需注册、无账号 | 管理员开号、**必须登录** |
| 使用范围 | 仅自己 | 全公司（≤50 人），数据彼此隔离 |
| 数据存放 | 仅本机 | 本机 + 公司服务器 |
| 待办共享 | — | **不做**（各人管各人） |
| 离线可用 | 天然可用 | **必须离线优先**（断网照常用） |

## 1. 系统组成

整个软件由**三个部分**构成：

```
┌─────────────────┐        ┌──────────────────┐        ┌─────────────────┐
│  ① 客户端        │  HTTPS │  ② 服务端         │        │  ③ 管理后台      │
│  Windows 桌面    │ ─────► │  认证 / 存数据    │ ◄───── │  网页版（浏览器）│
│  挂件 + 四大模块  │        │  / 判冲突         │        │  建号/改密/停用  │
└─────────────────┘        └──────────────────┘        └─────────────────┘
```

| 部分 | 形态 | 谁用 | 第一版是否要做 |
|---|---|---|---|
| ① 客户端 | Windows 桌面程序 | 全体员工 | ✅ 是 |
| ② 服务端 | Docker 部署在公网服务器 | 无人直接使用 | ✅ 是 |
| ③ 管理后台 | 网页（浏览器打开） | 管理员（你） | ✅ 是 |

**管理后台做成网页的原因**：管理员在电脑上用浏览器操作最方便，不用再装一个程序。50 人以内，功能极简。

## 2. 账号与登录

### 2.1 无注册，只开号

- **没有注册功能**。账号由管理员在管理后台手工创建。
- 建号只需三项：`登录名`、`姓名`、`初始密码`。
- 人员很少，**不需要** Excel 批量导入，也**不需要**对接 AD / 钉钉 / 企业微信。

### 2.2 登录流程

1. 首次打开客户端 → 显示登录窗
2. 输入管理员给的登录名 + 初始密码
3. **强制修改密码**（初始密码只能用这一次）
4. 改完进入主界面
5. **此后永久记住登录状态**，除非用户手动退出

> 为什么必须"永久记住"：员工每天开电脑都要输密码的桌面工具，一定会被弃用。凭据长效保存是本软件的生存线。

### 2.3 密码与安全

| 项 | 规则 |
|---|---|
| 密码强度 | 至少 6 位，建议含字母+数字（不强制过度复杂） |
| 连续输错 | 5 次 → 锁定 15 分钟 |
| 忘记密码 | **找管理员重置**（无邮箱、无自助找回） |
| 管理员重置后 | 用户下次登录再次强制改密 |
| 离职处理 | 管理员停用账号，数据保留不删 |

### 2.4 登录态失效的降级（重要）

服务器连不上时，**不能把用户挡在门外**：

- 已登录过的设备 → 凭据本地长效有效，**断网照常使用**
- 服务器恢复后自动重新同步
- 只有在**从未登录过的新设备**上，才必须联网登录一次

## 3. 权限与隐私边界

### 3.1 铁律：管理员看不到任何人的待办内容

| 角色 | 能做 | **不能做** |
|---|---|---|
| 普通用户 | 读写**自己的**待办与随笔 | 看到别人的任何数据 |
| 管理员 | 建号、重置密码、停用/启用账号、看用户列表 | **查看任何用户的待办内容** |

**技术保证**：服务端接口只允许本人读写自己的数据；管理接口在设计上**不提供内容查询能力**。

**为什么要写死这条**：如果员工知道 IT 能翻自己的待办，就不会记真话；记假话的待办工具等于没有。**这是这个软件能不能被真正用起来的信任基础。**

### 3.2 不做共享待办

- 不做"派活给同事"、不做"部门共享清单"、不做"@某人"
- 每个人的清单就是自己的私人空间
- 需要协作的事，走公司现有的 OA / 群里沟通，不混进这个工具

## 4. 数据模型

### 4.1 「事项」的字段

| 字段 | 必填 | 说明 |
|---|---|---|
| 内容 | 是 | 一句话，最多约 200 字 |
| 日期 | 否 | 哪一天做。**空 = 未排期，自动进「随笔」区** |
| 时间 | 否 | 几点几分。**空 = 全天事项** |
| 提醒开关 | 是 | 有时间默认开；无时间默认关 |
| 提前量 | 否 | 提前 0 / 5 / 15 / 30 / 60 分钟，默认 0 |
| 重复规则 | 否 | 不重复 / 每天 / 每周（选周几）/ 每月（选几号）/ 工作日 |
| 状态 | 是 | 未完成 / 已完成 / 已取消 |
| 顺延次数 | 是 | 被推迟过几次（**核心字段**，默认 0） |
| 完成时间 | 否 | 用于归档 |
| 备注 | 否 | 折叠，展开才看到 |

### 4.2 核心设计：一份数据，四个视角

「今天 / 明天 / 日历 / 随笔」**不是四个篮子，而是同一份数据的四种看法**：

| 视角 | 定义 |
|---|---|
| 今天清单 | 日期 = 今天的 |
| 明天清单 | 日期 = 明天的 |
| 日历 | 按日期摊开的总览 |
| 随笔 | **日期为空**的事项 |

好处：在日历上把事挪到明天，明天清单立刻就有，不用重复录入。

### 4.3 一天的起点 = 凌晨 04:00

- 凌晨 0 点到 4 点之间处理的事，**仍算"今天"**
- 理由：用户熬夜到凌晨 1 点还在干活，日历不该已经翻页
- 凌晨 4 点整，系统执行"翻页"：昨天未完成的进入逾期顺延

## 5. 四个模块

### 5.1 今天清单（早上做规划的人）

界面从上到下：

```
┌────────────────────────────────┐
│ 10月3日 周五      今天还有 4 件 │
├────────────────────────────────┤
│ ⚠ 昨日未完成 (2)          [收起]│
│   ☐ 给客户回电话      拖了 3 天 │
│   ☐ 报销单提交        拖了 1 天 │
├────────────────────────────────┤
│ ☐ 09:30  周会          🔁 每周 │
│ ☐ 14:00  评审原型稿            │
│ ☐ 17:00  交周报                │
│ ☐        买咖啡豆              │
├────────────────────────────────┤
│ ✓ 已完成 (3)              [展开]│
├────────────────────────────────┤
│ ＋ 添加今天的待办…             │
└────────────────────────────────┘
```

- 排序：按提醒时间升序；**无时间的排最后**
- 输入框敲回车即存，默认落到今天、默认无时间
- 顶部常驻：日期 + 未完成数量

### 5.2 明天清单（下班前做规划的人）

- 就是"日期 = 明天"的视图，与今天清单**共用同一套界面**，一个按钮切换
- 用途：下班前把明天的安排排好
- 明天清单顶部可显示"今天还剩 2 件没做完"的提醒（避免今天的事拖到明天）

### 5.3 日历清单（记录未来固定时间的事）

- 月视图，有事的日子下方打点（显示条数）
- 点某一天 → 列出当天事项
- 支持对某条 `改期`（第一版用按钮改期，**不做拖拽**）
- 日历是**查看与安排的入口**，不是第四个数据容器

### 5.4 随笔记录（抓住瞬间灵感）

- **全局快捷键**（如 `Ctrl+Alt+Q`）随时呼出输入框 → 输入 → 回车 → 存好，**不问任何问题**
- 存进去就是"未排期"状态，安静躺在随笔区，**不提醒、不打扰**
- 每条右侧有 `→ 排期`：一键变成今天 / 明天 / 某天的待办
- 定位：**待办的暂存区（Inbox）**，灵感不会烂在笔记本里

## 6. 三大核心机制

### 6.1 逾期顺延（本软件的灵魂）

1. 到了新的一天（凌晨 4 点），昨天及更早未完成的事项 **不删除、不改日期**
2. 它们自动出现在**今天清单最顶部**的「⚠ 昨日未完成 (N)」区域
3. 每条累计**顺延次数**，界面上直白显示"拖了 3 天"
4. 顺延次数 ≥ 3 时，温和提示：
   > 这件事已经放了 3 天了，要不要改个时间、拆小一点，或者放弃？
   按钮：`改期` / `今天一定做` / `放弃`
5. 区域内每条支持一键：`搬到今天` / `改期`

**为什么不在原日期上直接改**：保留原始日期 = 保留"这件事拖了多久"的真相。用户最需要看到的就是这个真相。

### 6.2 提醒引擎

#### 三级递进

| 阶段 | 时机 | 表现 |
|---|---|---|
| **L1 静默提示** | 到点瞬间 | 挂件图标**闪动** + 红色数字角标 + **响一声**。**不抢焦点**，不打断当前工作 |
| **L2 气泡确认** | L1 后 1 分钟仍未处理 | 弹小气泡：`完成` / `推后10分钟` / `推后1小时` / `今天不再提醒` |
| **L3 累积** | L2 后仍不处理 | 角标数字持续累积，**不重复弹窗**（避免烦人） |

#### 提醒风暴合并（生死线）

同一时刻多件事到点 → **合并成一条**：

> **你有 5 件事到点了**
> - 交周报
> - 给客户回电话
> - 评审原型稿
> - …
>
> `全部推后10分钟`　`逐个处理`

**绝对不允许弹出 5 个窗口**——那是用户第一天就卸载软件的原因。

#### 错过与漏提醒

- 电脑睡眠/关机期间错过的 → 开机后汇总一条「你错过了 3 个提醒」，**不逐个补弹**
- 全天事项（没设时间）→ 只在早上约定时间（如 09:00）汇总一次：「今天有 5 件事」

#### 免打扰

- 默认免打扰时段：**22:00 – 07:00**（可关闭、可改）
- 免打扰期间：只闪图标、**不响声音、不弹气泡**
- 例外：用户手动标记为"重要"的事项依然提醒

### 6.3 重复任务

第一版支持：不重复 / 每天 / 每周（选周几）/ 每月（选几号）/ 工作日。

| 规则 | 设计 |
|---|---|
| 生成方式 | **用到时才生成当天的实例**，不预先造几百条记录（保证速度） |
| 勾选完成 | **只完成这一次**，系列继续 |
| 不做某次 | 用「跳过本次」，而非删除 |
| 编辑 | 第一版统一「**修改整个系列**」，不做"只改这一次" |
| 删除 | 询问：`只删这一次` / `删除整个系列` |
| 界面标识 | 带 🔁 图标，一眼可辨 |

## 7. 桌面挂件（客户端外壳形态）

### 7.1 显示与隐藏

| 用户动作 | 软件反应 |
|---|---|
| 鼠标移到屏幕最右侧边缘的窄条 / 小图标 | 面板滑出（约 0.15 秒动画） |
| 鼠标移开 | **延迟 1.5 秒**再收起 |
| 正在输入文字 / 正在勾选 | 不收起 |
| **单击**小图标 | **钉住**（pin）常显，再点一次收起 |
| 双击 / 按 `Esc` | 收回到只留小图标 |

> 原始需求是"移开就隐藏"，但那样鼠标一滑出去、正在打的字就没了。加 1.5 秒延迟 + 输入时不收起 + 点击可钉住，体验才成立。

### 7.2 小图标的形态

- 位置：屏幕右侧垂直居中，宽约 6–10px 的窄条 + 小图标
- 常显信息：未完成数量角标
- 到点提醒时：**闪动**（即使鼠标不在附近）
- 特性：**不抢焦点、不占任务栏、不遮挡其他窗口操作**
- 系统托盘：常驻图标，可右键退出

### 7.3 视觉要求

- 面板宽度约 320–360px，高度自适应，最大不超过屏幕 80%
- 整体轻、快、无多余装饰
- **从点击到可输入应在 200ms 内**

### 7.4 其他客户端功能

- 开机自启（默认开，可关）
- 全局快捷键呼出（默认 `Ctrl+Alt+Q`，可改）
- 声音开关 / 音量 / 试听

## 8. 同步机制（离线优先）

### 8.1 核心原则

> **没网的时候，软件必须和联网时一模一样好用。**
> 记录、勾选、提醒 —— 全部先写本地，秒回；联网了再悄悄传上去。

### 8.2 同步时机

| 时机 | 说明 |
|---|---|
| 客户端启动时 | 拉一次全量/增量 |
| 改动后 5 秒 | 防抖后上传 |
| 每 5 分钟 | 定时拉取 |
| 手动 | 点"立即同步"按钮 |
| 网络恢复时 | 自动重试队列 |

### 8.3 冲突规则

| 情况 | 处理 |
|---|---|
| 同一条被两台设备改了 | **后改的赢**（按修改时间；待办场景几乎不真冲突） |
| 一端删除、一端修改 | **删除优先**（避免"删了又活过来"） |
| 服务器连不上 | 全部进本地队列，联网后按顺序补传 |

### 8.4 同步什么、不同步什么

| 同步 | 不同步（保留在本地） |
|---|---|
| 待办与随笔的内容、日期、时间、状态、顺延次数 | 窗口位置、面板展开状态、声音设置、快捷键 |
| 用户自己的设置（可选） | 临时 UI 状态 |

### 8.5 同步状态要给用户看得见

挂件上显示一个小状态点：
- 🟢 已同步
- 🟡 同步中
- 🔴 离线（N 条待上传）

**不能让用户不知道自己的数据传没传上去。**

## 9. 服务端职责（刻意做"笨"）

服务端**不认识**"待办""重复规则""逾期顺延"这些业务概念。它只做四件事：

1. **认证** —— 校验登录名/密码，发放长效凭据
2. **存数据** —— 按用户隔离地保存记录
3. **判冲突** —— 提供增量拉取（"给我某时间之后变过的记录"）
4. **管账号** —— 仅给管理后台用（建号/改密/停用），**不含内容查询**

**为什么故意做笨**：
- 代码少 → 不容易出 bug、不容易挂
- 业务逻辑只在客户端一处 → 改规则不用动服务器
- 服务器出问题也只是"暂时不同步"，**不影响用户干活**

## 10. 管理后台（网页版）

50 人以内，功能极简，只有一页：

| 功能 | 说明 |
|---|---|
| 用户列表 | 登录名、姓名、状态（正常/停用）、最后登录时间 |
| 新建账号 | 登录名 + 姓名 + 初始密码 |
| 重置密码 | 生成新初始密码，用户下次登录强制修改 |
| 停用 / 启用 | 离职停用，**数据保留** |
| 修改姓名 | 纠错 |

**明确不做**：查看用户待办、数据统计看板、角色权限体系（只有"管理员/普通用户"两种）、审计日志。

## 11. 分发、升级与运维

### 11.1 客户端分发

- 提供 Windows 安装包，群内发给员工安装
- **服务器地址内置在安装包里**，员工打开就能用，**不需要填任何配置**
- 首次登录用管理员给的账号密码

### 11.2 自动更新

- 启动时检查新版本
- 后台静默下载
- **重启后生效**（不打断用户工作）
- 有更新时在挂件上给一个不打扰的小提示

### 11.3 运维清单（必须有人长期负责）

| 事项 | 频率 | 后果（如果不做） |
|---|---|---|
| 数据库备份 | 每日 | 服务器一坏，全公司的待办全部丢失 |
| HTTPS 证书续期 | 自动/到期前 | 证书过期 = **全员连不上** |
| 服务健康检查 | 常驻 | 服务挂了没人知道 |
| 磁盘空间 | 每月 | 写不进新数据 |

> ⚠️ **这不是写代码的事，是运维的事。动手前先确认公司有人管这三项。**

## 12. 功能边界

### 12.1 第一版必做

**客户端（Windows）**
1. 登录 + 永久记住登录 + 强制首次改密
2. 今天清单（含昨日未完成自动带入）
3. 明天清单
4. 日历视图
5. 随笔收件箱 + 全局快捷键极速记录
6. 提醒引擎（三级递进 + 合并提醒 + 推后 + 免打扰 + 重复任务）
7. 桌面右侧挂件（悬停展开 / 点击钉住 / 延迟收起 / 闪动）
8. 系统托盘 + 开机自启
9. 本地缓存 + 离线可用 + 同步状态显示

**服务端**
10. 认证 + 增量同步 + 冲突裁决
11. Docker 部署 + 数据库 + HTTPS + 每日备份

**管理后台**
12. 建号 / 重置密码 / 停用启用

### 12.2 明确砍掉（避免变复杂）

- ❌ 注册功能、邮箱/短信找回密码

## 13. 平台路线图

**架构原则：大脑 / 同步层 / 外壳 三层分离**

| 层 | 内容 | 复用性 |
|---|---|---|
| **大脑** | 待办规则、重复规则、逾期顺延、提醒调度 | **一份，全平台共用** |
| **同步层** | 上传下载、冲突处理、离线队列 | **一份，全平台共用** |
| **外壳** | 界面、挂件、通知、托盘、自启 | 每个平台各做一层 |

| 顺序 | 平台 | 说明 |
|---|---|---|
| 1 | **Windows** | 第一版，把功能做扎实 |
| 2 | macOS | 换外壳 |
| 3 | Android | 换外壳 + 移动端交互调整 |
| 4 | 鸿蒙 OS | 换外壳（可能需专门方案） |
| 5 | iOS | 换外壳（如可行） |

服务端和账号体系天然支持全部平台，**不需要为每个平台重做后台**。
