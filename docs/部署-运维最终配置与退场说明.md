## 一、先说清楚：为什么这是最后一次

快办已经有**两个独立环境**，都在你们已交付的基础设施上跑着：

| 环境 | 机器 | Portainer | Stack 名 | Stack ID | 现状 |
|---|---|---|---|---|---|
| 测试 | `192.168.2.6` | `192.168.2.6:9000` | `kuaiban-test` | 5 | ✅ 运行中 |
| 生产 | `192.168.2.10` | `192.168.2.10:9000` | `kuaiban-production` | 5 | ✅ 运行中、当前外网未指到它 |

两端都已由我们通过 **Portainer API** 部署完毕、数据目录与镜像均在位、自检通过。

**现在只差一件事**：把外网域名的回源目标从测试机改成生产机，让生产机成为员工的正式入口。
**同时保留测试机只走内网 IP**，这样以后我们自己在内网就能完成全部"先测试、再上生产"的流程。

**做完本文第三节的 3 条，运维就再也不需要参与快办的日常迭代了。**

## 三、请执行的 3 条（★ 顺序不能颠倒 ★）

### 第 1 条：爱快新增端口映射

```
外网 16523  →  192.168.2.10:6522
```

**保留**现有的 `16522 → 192.168.2.6:6522` 不动（它不再是外网入口，留着无害）。

> 两个映射指向**不同机器**的同一个内部端口 `6522`，不冲突。

### 第 2 条：生产机 `.10` 放行防火墙 ★ **必须早于第 3 条** ★

```
放行 6522/tcp
来源限制：192.168.2.0/24 + 47.105.64.102
```

**这一条必须在改 NPM 之前完成**，否则第 3 条一做，外网立刻不通。

`.10` 上目前**尚未放行** 6522（此前只做了 `.6`），请确认这条做完再往下走。

### 第 3 条：阿里云 NPM 改回源端口

打开已有的 Proxy Host（**`kuaiban.bonnei.com`，id=13**），**只改一项**：

```
Forward Port:  16522  →  16523
```

其余**全部保持不变**：

| 项 | 保持 |
|---|---|
| Domain Names | `kuaiban.bonnei.com` |
| Scheme | `http` |
| Forward Hostname | `ddns.bonnei.com`（**动态域名，不要改成 IP**） |
| Block Common Exploits | 开 |
| Websockets Support | 开 |
| Force SSL | 开 |
| Advanced 的 `client_max_body_size 200m;` | 保留 |
| SSL 证书 | **不用动**（自动续期照旧） |

> 测试域名**不需要**新建 —— 测试机走内网 IP，不占外网入口。

## 四、请做的验收（做完 3 条后）

请在本机执行并回传结果：

```bash
# 1) 生产机是否已能直连
curl -sS --max-time 8 http://192.168.2.10:6522/api/health
#    期望：{"ok":true}

# 2) 域名是否已指向生产机（关键：看返回的账号里有没有 admin、以及版本）
curl -sS --max-time 15 https://kuaiban.bonnei.com/api/health
#    期望：{"ok":true}

# 3) 域名证书是否仍然有效
echo | openssl s_client -connect kuaiban.bonnei.com:443 \
  -servername kuaiban.bonnei.com 2>/dev/null | openssl x509 -noout -subject -dates
#    期望：CN=kuaiban.bonnei.com，到期日在 2027 年初

# 4) HTTP 是否仍强制跳 HTTPS
curl -sS -o /dev/null -w '%{http_code} %{redirect_url}\n' --max-time 10 http://kuaiban.bonnei.com/
#    期望：301 https://kuaiban.bonnei.com/

# 5) 下载页是否正常
curl -sS -o /dev/null -w '%{http_code}\n' --max-time 15 https://kuaiban.bonnei.com/
#    期望：200
```

**第 2 条的判定方式**：改完第 3 条后，`https://kuaiban.bonnei.com` 的后台里应当
**看不到**测试账号 `ceshi`（它只存在于测试机的数据库里）。若还能看到，说明回源仍指向
测试机，请检查第 3 条是否生效。

> 我们这边也会立刻做一次完整复验（登录、同步、下载页、自动更新清单）。

## 六、请遵守的既有约定（重申）

1. **不要改 Stack 名 / 容器名 / 项目名。** 快办的数据用宿主机目录
   `/opt/kuaiban/data` 挂载（不是命名卷），改名不会丢数据，但命名规范仍要遵守。
2. **回源一律用 `ddns.bonnei.com` 动态域名**，不要写死公网 IP（你们仓库的公网 IP 会变）。
3. **两台机器端口完全相同（都监听 6522），只能靠 IP 区分**：
   测试 `192.168.2.6:6522` / 生产 `192.168.2.10:6522`。改配置前先确认目标 IP。
4. **Portainer API Key**（描述名 `kuaiban-upgrade`，两台各一把）已用于快办服务端，
   存放在快办数据库里，**不在代码仓库、不在 compose 文件里**。
   请纳入台账并建议每年复核一次。
5. **`/opt/kuaiban/data` 里目前只有** `kuaiban.db`（+ WAL/SHM）与 `releases/`
   （客户端安装包缓存）。
   **更新签名私钥不在服务器上**（签名在 CI 完成），所以备份压力比预想的小。
